Why this matters

Why most people stay stuck at "AI curious"

The common loop

  • Consume tutorials and tool demos
  • Try prompts without a clear use case
  • Jump into code before defining the problem
  • Ignore the role of data and retrieval
  • End up with a vague demo and more confusion

The gap is not motivation. It is structure.

Builders work from one simple sequence:

problem → data → retrieval → generation → interface

AI curious asks "which tool is best?" AI builder asks "what system does this user problem need?"

Why enterprise HR is the right project

Employees ask the same questions again and again: how many leave days do I have, what is the sick-leave process, can I work remotely, how do I claim travel expenses. The answers exist, but they are buried in PDFs, handbooks, emails and portals. HR teams lose hours to repeat questions and employees lose time searching.

Repetitive

The same policy questions, every week.

Policy-based

Answers live in documents, so they can be grounded.

Measurable

You can test against known correct answers.

Portfolio-grade

Document-grounded assistants are the dominant enterprise AI pattern.

Why not just use ChatGPT, or just prompt a model?

A language model does not know your company's policies. If you ask it "how many annual leave days do DDS employees get?" it will produce a fluent guess. In HR, a confident wrong answer is worse than no answer. Retrieval-Augmented Generation fixes this by retrieving the relevant policy text first and forcing the model to answer from it.

Without RAG

  • Only general model knowledge
  • Higher hallucination risk
  • Weak grounding in company data
  • No way to point back to a source

With RAG

  • Answers based on internal documents
  • More relevant and useful responses
  • Much better fit for business workflows
  • Source file and page can be shown
The honest caveat

RAG reduces hallucination risk. It does not remove the need for testing. That is why the third phase of CPE is Evidence.

From tool user to system thinker

A tool user tries prompts inside a tool. A system thinker designs how information enters the system, how context is retrieved, how the model generates, how the user interacts, and how quality is checked. In the HR example: the user asks about leave; the system searches HR documents; the model writes the answer; the interface shows it; evaluation checks it is accurate and safe.

The LLM: the brain of your application

The LLM is the reasoning and language-generation layer. It interprets the question, uses the retrieved context, and writes a readable answer. But the LLM is not the company database. It becomes useful when connected to trusted policy context. In the app, Python sends questions to the model through an API and receives responses programmatically, instead of you chatting manually in a website.

Model selection is a decision framework, not a fixed ranking. The right model depends on the task, cost, latency, reasoning needs and privacy requirements. Simple routing or extraction may use a smaller model; complex reasoning or high-stakes answers may need stronger models and more careful evaluation. The public text leaderboard at arena.ai/leaderboard/text is a useful reference.

Reasoning versus generating: what the LLM actually does

In a RAG application the LLM does two different jobs inside one call, and it helps to separate them.

Reasoning

Deciding what to do with the retrieved context: Is this question about DDS HR at all? Does the retrieved text actually contain the answer? Which of two retrieved clauses applies? For "10 days of leave", which notice tier is it? Reasoning is where wrong answers are prevented.

Generating

Writing the answer in clear, professional language from the evidence that survived the reasoning step: concise, polite, step by step. Generation is where the user experience is created.

Two model families matter here. A standard (non-reasoning) chat model answers directly. A reasoning model spends extra hidden "thinking" tokens before answering: it is slower and costs more (thinking tokens are billed as output), and it earns that cost on hard multi-step problems such as maths, coding and complex planning.

DecisionOur choiceWhy
Model classSmall, fast, low-cost chat modelIn RAG the retriever does the heavy lifting. The model reads 2 to 4 short chunks and summarises them. A frontier or pro reasoning model would add cost and latency for little gain.
Temperature0.2Low temperature keeps answers stable and factual. HR policy is not creative writing.
Where "reasoning" livesIn the promptThe system prompt tells the model to check scope and evidence before answering. The course app says "always reason before concluding". The hardened version says to determine this silently and never reveal private reasoning.
When to upgradeWhen evaluation shows failuresIf tests show the model misapplying policy logic (for example tiered notice rules), try a stronger model on the failing questions. Test first, then pay.
The LLM reasons over evidence, then generates. Retrieval decides what evidence it sees, and that is why we spend Day 2 on retrieval rather than on picking the fanciest model.

Configure the models (LlamaIndex Settings)

Settings is LlamaIndex's global configuration. Set it once and every component (index, retriever, query engine) uses it.

Colab cell 2: keys and global settings
import os
from llama_index.core import Settings
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding

# LLM: writes the final answer. Low temperature = stable, factual.
Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0.2)

# Embedding model: turns text into a 1536-number vector.
Settings.embed_model = OpenAIEmbedding(model="text-embedding-ada-002")

# Chunking parameters (explained below)
Settings.chunk_size = 600
Settings.chunk_overlap = 200
Model names are just configuration

The reference app uses gpt-4o-mini for chat and text-embedding-ada-002 for embeddings. The hardened live-demo version uses text-embedding-3-small. Both produce 1536-dimension vectors. To use the Day 1 recommendation, change the strings to gpt-5.4-nano and text-embedding-3-small. One rule you cannot bend: the model you embed with at indexing time must be the same model you use for queries, and the Pinecone index dimension must match it.

Step 1: Load the documents

SimpleDirectoryReader walks a folder and reads every file. We give it PDFReader for PDFs. It returns a list of Document objects.

from llama_index.core import SimpleDirectoryReader
from llama_index.readers.file import PDFReader

documents = SimpleDirectoryReader(

Step 2: Chunking

A page is too big and too mixed to be a good search unit. If you embed a whole page about sick leave, maternity leave and public holidays as one vector, the meaning is blurred. Chunking splits documents into passages small enough to be about one thing, but large enough to keep context.

Chunk size: 600

Measured in tokens (about 450 words). Enough to hold a full policy clause with its numbers.

Overlap: 200

Each chunk repeats the last 200 tokens of the previous one, so a sentence or rule split at a boundary is still whole in at least one chunk.

Splitter

SentenceSplitter is LlamaIndex's default. It prefers to break on sentence boundaries rather than mid-sentence.

Colab cell 4: inspect the chunks yourself
from llama_index.core.node_parser import SentenceSplitter

print(len(nodes))            # 15 chunks (called "nodes" in LlamaIndex)
print(nodes[3].text[:400])   # read a chunk
print(nodes[3].metadata)     # metadata is inherited from the page

Larger chunks give more context but blur the topic. Overlap costs a few extra vectors and protects against split rules. There is no universal best value: tune chunk size by testing retrieval on real questions.

Step 3: Embeddings, the 1536 numbers

A computer cannot compare meaning in raw text. An embedding model converts a piece of text into a list of numbers (a vector) placed in a high-dimensional space so that texts with similar meaning land close together. "How many vacation days do I get?" and "annual leave entitlement" share almost no words, yet their vectors are close. That is semantic search, and it is why RAG beats keyword search for policies.

Colab cell 5: see an embedding
vec = Settings.embed_model.get_text_embedding(
    "Full-time employees are entitled to 22 working days of paid annual leave."
)
print(len(vec))     # 1536
print(vec[:5])      # five floats, e.g. 0.0123, -0.0087, ...

q = Settings.embed_model.get_query_embedding("How many vacation days do I get?")
print(len(q))       # 1536  (same space as the chunks, so they are comparable)

Why exactly 1536?

It is the output size of OpenAI's text-embedding-ada-002 and of text-embedding-3-small by default. Each chunk becomes 1536 floating-point numbers, about 6 KB (1536 x 4 bytes). text-embedding-3-large outputs 3072. The vector database index must be created with exactly the same dimension.

How similarity is measured

The vector database finds the stored vectors nearest to the question's vector using a distance metric: cosine (angle), euclidean (straight-line distance) or dot product. OpenAI embeddings are normalised to length 1, so all three rank results identically. The course app uses euclidean; the hardened version uses cosine.

Cost: our whole knowledge base is roughly 15 chunks, so embedding it costs a fraction of a cent. That is why you index once and reuse, rather than re-embedding on every restart.

Step 4: Store it first in LlamaIndex (in memory)

VectorStoreIndex is the object that ties everything together. When you call from_documents it chunks the documents, calls the embedding model for every chunk, and keeps the vectors in LlamaIndex's built-in in-memory vector store.

Colab cell 6: build the first index
from llama_index.core import VectorStoreIndex

index = VectorStoreIndex.from_documents(documents, show_progress=True)

query_engine = index.as_query_engine()
print(query_engine.query("How many days of annual leave do employees get?"))

This is the fastest way to a working RAG loop and it is perfect for learning. Its limit is in the name: memory is temporary. Restart the notebook and the vectors are gone, and you pay to embed everything again.

Local files vs a vector database

Persisting to JSON is simple and free but lives on one machine and is loaded fully into memory. A real deployment needs a managed vector database that is shared, scalable, searchable across users and survives restarts. That is Pinecone.

Step 6: Pinecone, the vector database

Pinecone stores your vectors as a managed service and does fast nearest-neighbour search. The key setup decisions are the index name, the dimension (1536), the metric and the region.

Colab cell 9: create or attach a Pinecone index
from pinecone import Pinecone, ServerlessSpec
from llama_index.vector_stores.pinecone import PineconeVectorStore
from llama_index.core import StorageContext, VectorStoreIndex

pc = Pinecone(api_key=os.environ["PINECONE_API_KEY"])

INDEX_NAME = "quickstart"
DIMENSION  = 1536            # must equal the embedding model's output size

if INDEX_NAME not in [i["name"] for i in pc.list_indexes()]:
    pc.create_index(
        name=INDEX_NAME,
        dimension=DIMENSION,
        metric="euclidean",   # cosine also works; OpenAI vectors are normalised
        spec=ServerlessSpec(cloud="aws", region="us-east-1"),
    )

pinecone_index = pc.Index(INDEX_NAME)
vector_store   = PineconeVectorStore(pinecone_index=pinecone_index)

storage_context = StorageContext.from_defaults(vector_store=vector_store)
index = VectorStoreIndex.from_documents(
    documents, storage_context=storage_context
)

Notice the only change from Step 4 is storage_context: we tell LlamaIndex to put the vectors in Pinecone instead of memory. Everything else is identical. That is the point of an orchestration framework.

Create once, reuse forever

The app checks whether the index already holds vectors with describe_index_stats(). If yes it attaches with VectorStoreIndex.from_vector_store(vector_store). If no it loads the PDFs and builds. Deleting and recreating on every restart would re-embed every PDF (real API cost) and risks a race between two cold starts.

Three ways to fail

Dimension mismatch (index made for a different embedding model). Empty index (the build step never ran). Wrong namespace (the hardened app writes to a namespace such as dds-hr-v1). Check describe_index_stats() first.

A vector alone is just numbers. Metadata is what makes an answer traceable. LlamaIndex attaches metadata to every chunk and it travels into Pinecone with the vector.

Metadata caution

Metadata from file_path can leak local folder names, and metadata that is embedded with the text can shift similarity slightly. For sensitive deployments, control which keys are shown to the model and to the user.

Step 7: The retriever

The retriever is the component that answers: "given this question, which chunks should the model see?" It embeds the question with the same embedding model, asks Pinecone for the closest vectors, and returns the top-k chunks with similarity scores.

Colab cell 10: retrieve without the LLM
retriever = index.as_retriever(similarity_top_k=4)

results = retriever.retrieve("How much notice do I need for 10 days of annual leave?")

for r in results:
    print(round(r.score, 3), r.node.metadata["file_name"], "p.", r.node.metadata["page_label"])
    print(r.node.text[:250].replace("\n", " "))
    print("-" * 60)

similarity_top_k

How many chunks to return. LlamaIndex default is 2; the hardened app uses 4. Too low misses supporting clauses; too high adds noise and cost.

Score

How close the chunk is to the question. Use it to spot weak retrieval: if the top score is poor, the answer will be poor.

Debug retrieval first

If the retrieved text does not contain the answer, no prompt or model can fix it. Always look at retrieval before blaming the LLM.

This is the most valuable debugging habit in RAG: retrieval and generation fail for different reasons. Bad retrieval means wrong chunks (fix chunking, top-k, data). Bad generation means the right chunks but a wrong or ungrounded answer (fix the prompt or model).

Query engine: putting retrieval and the LLM together

The query engine wraps the retriever, the prompt template and the LLM into one call. You supply a QA prompt template with two placeholders: {context_str} (the retrieved chunks) and {query_str} (the question).

from llama_index.core import PromptTemplate

The math under the hood Foundations Masterclass recap

Four ideas from the DDS Foundations Masterclasses that make the pipeline above actually work. Everything below is computed live from your current query and the real chunks — not canned numbers.

01 Cosine similarity — how "close" is measured

Every ranking you saw on the Retriever tab comes down to one formula: the cosine of the angle between two vectors. It ignores length and only cares about direction — so a short chunk and a long chunk that talk about the same thing can still score close to 1.0.

cos(θ) = (A · B) / (‖A‖ × ‖B‖)

02 Attention — why the model weighs some words more

Before any of this, the transformer itself decides which words in your query to "attend to" using Query/Key/Value projections of the token embeddings, then scales by √dₖ before softmax. This demo can't run real attention weights in your browser, but the highlighted words below show the same idea in miniature: which terms in the top-ranked chunk actually carried the retrieval.

QUERY (Q)

What am I looking for? Your typed question, projected into the same space as every chunk.

KEY (K)

What does each chunk offer? Every one of the 10 chunks gets its own Key vector to match against.

VALUE (V)

What gets passed forward? The actual chunk content the LLM reads once it's picked as a match.

03 Retrieval metrics — did it actually find the right thing?

"It returned an answer" isn't the same as "it returned the right answer." These are the four metrics from the Retrieval Metrics masterclass, computed live against a hand-labeled ground truth for your current query — the same numbers a real evaluation harness would log for every query in production.

04 Perplexity & KL divergence — how the LLM "feels" about grounding

Perplexity measures how surprised a language model is by its own output — low perplexity means it was confident in the next word it picked. When Ayesha answers from a retrieved chunk that clearly contains the fact, the correct next tokens are highly probable and perplexity drops. When a query isn't grounded in any chunk (like the wifi-password example), the model has nothing to anchor to, uncertainty rises, and a well-built system should prefer refusing over guessing — which is exactly the rule baked into Ayesha's system prompt. KL divergence is the same idea one level up: it's how the DDS team measures how far a fine-tuned model's answer distribution has drifted from the base model's, to make sure grounding rules like "always cite, never guess" actually stuck after training.

Below are 12 questions with the answer the documents actually support, checked against the four PDFs. Click a question to see the expected behaviour and source. Use these to score your own bot.

1. What is the annual leave policy? Answerable

Full-time employees get 22 working days of paid annual leave per leave year (pro-rata for part-time and mid-year joiners). It accrues at 1.83 days per completed month. Max single block is 15 consecutive working days; at least one continuous block of 5 days must be taken each year.

Source: Leave Policy v2, section 3.

2. How much notice do I need for 10 days of annual leave? Answerable

30 calendar days for 10 or more working days (14 days for 3 to 9 working days; 7 days for 1 to 2 days). Managers respond within 3 business days. A good bot picks the correct tier, which tests reasoning as well as retrieval.

Source: Leave Policy v2, section 3.4.

3. How many sick leave days do I get and do I need a medical certificate? Answerable

15 working days per year at full pay, after probation. Notify your manager within 1 hour of your normal start time. A medical certificate is required for 2 or more consecutive working days. Beyond 15 days, up to 30 further calendar days at half pay, then up to 45 unpaid, with documentation.

Source: Leave Policy v2, section 5; HR FAQ.

4. Can I carry over unused leave? Answerable

Up to 10 unused days carry into the next year automatically, and must be used by 31 March, or they expire without compensation. Unused leave is not paid out during employment; on termination, accrued unused leave is paid at the basic salary rate.

Source: Leave Policy v2, section 4.

5. What are the maternity leave rules? Answerable

60 calendar days at full pay, exceeding the statutory minimum. Notify HR at least 30 calendar days before the expected date, with medical documentation. Leave can start up to 30 days before delivery. Nursing breaks: one paid hour per day for 6 months after return.

Source: Leave Policy v2, section 7.1 to 7.2.

6. Can I work remotely full-time? Conditional

It depends on role suitability, performance and operational needs, with line-manager approval. HR may set role-based constraints (event roles need onsite presence), and remote status can be revoked. The bot should not answer a flat yes or no.

Source: Remote Work Policy, section 2; HR FAQ.

7. What are the core collaboration hours? Partial

Teams set their own core hours where meetings may be scheduled; the handbook gives 12:00 to 16:00 GST as an example. Standard Dubai office hours are 9:00 to 18:00, Monday to Friday. A careful bot says "for example" rather than presenting the example as a rule.

Source: Employee Handbook, section 6.

8. Can I paste confidential DDS data into a public AI tool? Answerable

No. Do not paste confidential data into public chatbots unless an approved enterprise environment is in place. Use approved model providers and enterprise settings for sensitive data, verify AI outputs, and do not treat AI as a source of truth.

Source: Employee Handbook sections 12 and 13; Remote Work Policy section 5.

9. I booked a non-refundable flight before my leave was approved. What should I do? Edge case

The policy says employees should not book non-refundable travel before approval is confirmed in the leave system, but it does not say what to do afterwards. A good bot states what the policy says, admits the gap, and points to the manager or HR for the case-specific situation.

Source: Leave Policy v2, section 3.4.

10. I saw harassment but I am not the victim. Can I still report it? Edge case

Concerns can be raised with HR or a People Partner (or the manager where appropriate). Reports are handled confidentially to the extent possible and retaliation for good-faith reports is prohibited. The documents do not restrict reporting to victims, and the bot should not invent a rule either way.

Source: Employee Handbook section 4; HR FAQ.

11. What is the salary range for a data scientist? Must decline

Out of scope and confidential. Expected: the decline message with the contact email. Not answering, and not guessing a number, is the correct behaviour.

Tests: scope control and the "no salary information" rule.

12. What is the resignation notice period? Must decline or qualify

The handbook says notice periods are defined in your offer letter or contract, and gives no number. A grounded bot must not supply a typical figure from general knowledge. It should say the handbook does not specify it and refer the user to HR or their contract.

Tests: refusal to fill gaps from general knowledge, the most important hallucination test.

What to observe in every answer

  • Is it relevant and grounded in retrieved text?
  • Does it stay in HR scope?
  • Does it avoid guessing when context is missing?
  • Is the tone professional and clear?
  • Does it handle edge cases calmly and escalate?

def _get_value(value: Any, key: str, default: Any = None) -> Any:
    """Read a field from either a Pinecone object or dictionary."""
    if isinstance(value, dict):
        return value.get(key, default)
    return getattr(value, key, default)


def _index_is_ready(description: Any) -> bool:
    status = _get_value(description, "status", {})
    return bool(_get_value(status, "ready", False))


def _namespace_vector_count(
    pinecone_index: Any,
    namespace: str,
) -> int:
    stats = pinecone_index.describe_index_stats()
    namespaces = _get_value(stats, "namespaces", {}) or {}
    namespace_stats = namespaces.get(namespace)

    if namespace_stats is None:
        return 0

    return int(_get_value(namespace_stats, "vector_count", 0) or 0)


def _validate_existing_index(description: Any) -> None:
    existing_dimension = _get_value(description, "dimension")
    existing_metric = _get_value(description, "metric")

    if (
        existing_dimension is not None
        and int(existing_dimension) != EMBEDDING_DIMENSION
    ):
        raise RuntimeError(
            f"Pinecone index '{INDEX_NAME}' has dimension "
            f"{existing_dimension}, but this app requires "
            f"{EMBEDDING_DIMENSION}. Use a new PINECONE_INDEX_NAME or delete "
            "the incompatible index manually."
        )

    if (
        existing_metric is not None
        and str(existing_metric).lower() != "cosine"
    ):
        raise RuntimeError(
            f"Pinecone index '{INDEX_NAME}' uses metric "
            f"'{existing_metric}', but this app requires 'cosine'. "
            "Use a new PINECONE_INDEX_NAME or recreate the index manually."
        )


def get_or_create_pinecone_index() -> Any:
    pc = Pinecone(api_key=PINECONE_API_KEY)
    existing_names = pc.list_indexes().names()

    if INDEX_NAME not in existing_names:
        logger.info("Creating Pinecone index '%s'...", INDEX_NAME)

        pc.create_index(
            name=INDEX_NAME,
            dimension=EMBEDDING_DIMENSION,
            metric="cosine",
            spec=ServerlessSpec(
                cloud="aws",
                region="us-east-1",
            ),
        )

        for _ in range(90):
            description = pc.describe_index(INDEX_NAME)

            if _index_is_ready(description):
                logger.info("Pinecone index is ready.")
                break

            time.sleep(2)
        else:
            raise TimeoutError(
                f"Pinecone index '{INDEX_NAME}' was not ready after "
                "three minutes."
            )
    else:
        description = pc.describe_index(INDEX_NAME)
        _validate_existing_index(description)
        logger.info("Using existing Pinecone index '%s'.", INDEX_NAME)

    return pc.Index(INDEX_NAME)

def load_pdf_documents():
    if not DATA_DIR.exists():
        raise FileNotFoundError(
            "The lowercase 'data' folder is missing. Create it and upload "
            "the DDS HR Handbook PDF."
        )

    pdf_files = sorted(DATA_DIR.glob("*.pdf"))

    if not pdf_files:
        raise FileNotFoundError(
            "No PDF was found in the lowercase 'data' folder. Upload the DDS "
            "HR Handbook PDF before restarting the Space."
        )

    logger.info(
        "Loading %d PDF file(s): %s",
        len(pdf_files),
        ", ".join(path.name for path in pdf_files),
    )

    documents = SimpleDirectoryReader(
        input_dir=str(DATA_DIR),
        required_exts=[".pdf"],
        file_extractor={".pdf": PDFReader()},
    ).load_data()

    if not documents:
        raise ValueError(
            "The PDF files were found, but no text was extracted. Ensure the "
            "handbook contains selectable text and is not only scanned images."
        )

    logger.info("Loaded %d document node(s).", len(documents))
    return documents


def build_query_engine():
    pinecone_index = get_or_create_pinecone_index()

    if FORCE_REINDEX:
        logger.warning(
            "FORCE_REINDEX=true. Deleting vectors only from namespace '%s'.",
            NAMESPACE,
        )
        pinecone_index.delete(
            delete_all=True,
            namespace=NAMESPACE,
        )
        time.sleep(2)

    vector_store = PineconeVectorStore(
        pinecone_index=pinecone_index,
        namespace=NAMESPACE,
    )

    vector_count = _namespace_vector_count(
        pinecone_index,
        NAMESPACE,
    )

    if vector_count == 0:
        logger.info(
            "Namespace '%s' is empty. Indexing the uploaded handbook...",
            NAMESPACE,
        )

        documents = load_pdf_documents()

        storage_context = StorageContext.from_defaults(
            vector_store=vector_store,
        )

        index = VectorStoreIndex.from_documents(
            documents,
            storage_context=storage_context,
            show_progress=True,
        )

        logger.info("Handbook indexing completed.")
    else:
        logger.info(
            "Reusing %d existing vector(s) from namespace '%s'.",
            vector_count,
            NAMESPACE,
        )

        index = VectorStoreIndex.from_vector_store(
            vector_store=vector_store,
            embed_model=Settings.embed_model,
        )

    return index.as_query_engine(
        llm=Settings.llm,
        similarity_top_k=4,
        response_mode="compact",
    )

query_engine = build_query_engine()

def _format_sources(response: Any) -> str:
    source_nodes = getattr(response, "source_nodes", None) or []
    sources: list[str] = []

    for source in source_nodes[:3]:
        node = getattr(source, "node", None)
        metadata = getattr(node, "metadata", {}) or {}

        file_name = metadata.get("file_name") or metadata.get("filename")
        page = (
            metadata.get("page_label")
            or metadata.get("page_number")
            or metadata.get("page")
        )

        if not file_name:
            continue

        label = str(file_name)
        if page is not None:
            label += f", page {page}"

        if label not in sources:
            sources.append(label)

    if not sources:
        return ""

    return "\n\n**Retrieved from:** " + "; ".join(sources)


def query_doc(question: str) -> str:
    question = (question or "").strip()

    if not question:
        return "Please enter a question about a DDS HR policy."

    try:
        response = query_engine.query(question)
        answer = str(response).strip()

        if not answer:
            return DECLINE_MESSAGE

        return answer + _format_sources(response)

    except Exception:
        logger.exception("A query failed.")
        return (
            "I could not process your question right now. Please try again "
            "or email connect@decodingdatascience.com."
        )

Troubleshooting

My Pinecone index is empty or returns no results

Check pinecone_index.describe_index_stats(). If the vector count is 0, the build step never ran or wrote to a different namespace. Confirm the namespace in the code matches the one you query, and that the PDFs actually loaded (documents count above zero).

Error: dimension mismatch

The Pinecone index dimension must equal the embedding model's output. Both ada-002 and text-embedding-3-small are 1536; text-embedding-3-large is 3072. Use a new index name or delete the incompatible index, then rebuild. Never mix embedding models between indexing and querying.

The chatbot gives generic answers

Print the retrieved chunks. If they do not contain the answer, fix retrieval (chunk size, top-k, missing document). If they do, tighten the system prompt: "use only the provided context", "say clearly when information is missing".

"No PDF documents were loaded"

Folder name case: Data vs data must match the code exactly. Also confirm the PDFs have selectable text (scanned images need OCR) and that the files were uploaded next to app.py.

"OPENAI_API_KEY is not set" on Hugging Face

Add the secret under Settings → Variables and secrets with the exact name, then restart the Space. Secrets are not read from your notebook or from a .env file you did not upload.

The Space re-embeds the PDFs on every restart

The index check is not finding existing vectors, usually because the index name or namespace changed between runs. Keep INDEX_NAME and NAMESPACE constant. In the logs you want "Reusing N existing vector(s)".

The build fails on Hugging Face

Read the build log. Common causes: a package missing from requirements.txt, a notebook command like !pip install left in app.py, or an unpinned library that changed. Pinned versions make builds reproducible. If deployment still fails, document the error and screenshots as evidence.

Can I use my own HR documents?

Yes, if they are approved for sharing and processing and are text-based PDFs. Do not use confidential employee data. For learning, use the synthetic DDS documents.

How do I make answers cite their source?

Read response.source_nodes and append file name and page from the metadata, as in the "Retrieved from" function in the Gradio section.

How would this become production-ready?

Add authentication and role-based access, logging and monitoring, PII protection, human escalation, evaluation pipelines, and data governance. The prototype is the foundation, not the end state.
