About the bootcamp

One company, one topic, three layers

The company is Decoding Data Science (DDS). The topic is employee leave. HR answers the same questions every week: how many days do I have, how much notice do I need, who approves. DecoBot answers them. Each day adds one layer.

Layer 1 | Day 1

Behaviour

A system prompt gives the AI a job, a scope and rules. It learns to refuse, and to ask one question when a request is unclear.

Layer 2 | Day 2

Knowledge

RAG lets DecoBot answer from the real policy PDF. You learn how chunking and embeddings decide whether it answers well.

Layer 3 | Day 3

Data and action

SQL tools give DecoBot your personal numbers. An agent chooses between the policy and the database, or uses both.

Part 1 | The PDF

Step 1 | Read

By eye: can you select and copy the text? Note headings, tables, version and date. With code, extract_text() gives one string per page. Keep the page number: it becomes the citation later.

Step 2 | Profile

4 pages. About 1,770 words, roughly 11,000 characters. 12 numbered sections, from "1. Leave Entitlements at a Glance" to "12. Governance". Top words: leave, days, calendar, working, notice.

Step 3 | Chunk

Cut the text so it can be searched. Size 1,200 characters and overlap 200 gives about 12 chunks. Too big is noisy, too small cuts a rule in half. Test it in the Chunking lab.

from pypdf import PdfReader
reader = PdfReader("DDS_Leave_Policy_v2.pdf")
pages = [p.extract_text() for p in reader.pages]
print(len(pages), "pages")          # 4
print(pages[0][:300])
Before you trust a PDF, check: text extracts cleanly, headings are numbered, tables did not break, the version and date are clear (version 2.0, effective 1 July 2026).

Part 2 | The database

Step 1 | Structure

employees (100 rows) and leave_requests (273 rows), linked by employee_id. Balances in employees were computed from the requests, so the tables agree.

Step 2 | Read with code

Pandas turns each table into a data frame you can count, filter and chart. Look at ten rows first, and read the column names out loud.

Step 3 | Quality

Five checks return zero issues. One is worth a look: 14 requests are dated after the simulated today (28 Oct 2026). Synthetic data, so we note it and move on.

Step 4 | What it says

203 of 273 requests are annual leave, 64 are sick. Average annual days left is 14.5, and the range is 0 to 22. Aisha Khan has 2 left.

Simulations

Labs

Change a setting and watch what happens. Labs marked "toy" use a simplified model so the idea is visible. They never pretend to be Gemini.

Chunking lab

The real DDS Leave Policy v2 text (about 11,000 characters). The amber band is the notice table in section 3.4 (7, 14 and 30 days). If a chunk boundary cuts through it, the bot may read only part of the table.

Sizes here are in characters. LlamaIndex counts tokens (about 4 characters each) and cuts at sentence ends. This lab cuts at exact characters, so counts differ a little from the notebook.

Retrieval and top_k lab (toy)

A question is compared with every chunk. The best top_k chunks go to Gemini. This toy retriever uses keywords plus a few synonyms so you can see the ranking. Real Gemini embeddings understand meaning far better.

Embeddings and dimensions lab

An embedding is a list of numbers. The number of numbers is the dimension. The vector database index must use the same dimension as the embedding model.

Phrases with similar meaning sit close together, even without shared words. The bot finds "annual leave" for a "vacation days" question because they are neighbours.

Agent router lab

An agent reads the question, picks the tool, reads the result and writes the answer. Employee data below is real, from dds_leave.db. The reply text is a simulation of what DecoBot is told to say, not a live Gemini call.

Today in the simulation is 2026-10-28. Notice rule: 1-2 working days need 7 calendar days, 3-9 need 14, 10 or more need 30.

Cost calculator

Gemini API prices in US dollars per 1 million tokens, from Google's pricing page checked on 30 Oct 2026. Prices are editable. Always confirm on ai.google.dev/gemini-api/docs/pricing before you budget.

input tokens  = calls x (system 330 + tools 400 + question 30)
              + top_k x chunk tokens + tool output 150 x (calls - 1)
output tokens = answer 120 + 40 x (calls - 1)
cost / question = input x in-price + output x out-price
embedding (one time) = chunks x chunk tokens x $0.15 / 1M
vector storage = vectors x dimensions x 4 bytes
Assumptions are rounded teaching values. Real usage depends on your prompt length and how often the agent loops.

from pinecone import Pinecone
from llama_index.core import VectorStoreIndex
from llama_index.vector_stores.pinecone import PineconeVectorStore

pc = Pinecone(api_key=os.environ["PINECONE_API_KEY"])
store = PineconeVectorStore(pinecone_index=pc.Index("dds-leave-policy"))
index = VectorStoreIndex.from_vector_store(store)      # no embedding at start-up

Before class

What to know before class

Untested live

The Gemini and Pinecone calls were not run end to end by the builder. Run each notebook once with your own keys.

Policy quirks

The policy does not define the probation period (the handbook only says "as stated in the employment contract"). Section 1 points to 4.4 for extended illness, but the content is in 5.4.

Not security

A prompt that says "refuse other people's data" is not security. A real site needs company login and tools locked to the signed-in employee.

Prices move

Gemini prices change, some on fixed dates. The calculator is a planning tool, not an invoice.
